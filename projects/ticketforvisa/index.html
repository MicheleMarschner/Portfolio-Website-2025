01 / THE PROJECT

Project Overview

ticketforvisa is a production web application developed for a client offering flight reservations for visa applications and international travel requirements.

The platform guides customers through a multi-step booking process, from selecting flights and entering passenger details to completing payment.

I developed the website independently as a freelance full-stack developer, taking responsibility for the entire technical implementation, from frontend and backend development to third-party integrations and deployment.

02 / TECHNICAL IMPLEMENTATION

How It Works

Customers can request a flight reservation through the website, complete the booking and payment online, and have their booking details automatically forwarded to the customer service team for further processing.

01 Website

Clicking the booking button opens the reservation form in a separate browser window.

02 Booking Form

Customers are guided through a multi-step form, selecting flights with Fuse.js-assisted search before entering passenger details.

03 Payment

Customers can choose between multiple payment methods through the integrated PayPal checkout.

04 Internal Notification

Booking details are emailed to the customer service team via Resend, with notification jobs stored in Redis for asynchronous processing and retries if needed.

03 / TECHNICAL CHALLENGES

Challenges & Solutions

01

State Consistency & Persistence

Challenge

In a multi-step booking form, user inputs must remain available when navigating between steps or returning to the page. A particular risk arises when restoring data from localStorage: the initial empty React state can overwrite previously saved information before it has been loaded.

Implemented Solution

A centralized React Context serves as the single source of truth for form data, with localStorage providing persistence across sessions. Saved data is validated with Zod during initialization, and updates to localStorage are only enabled once existing data has been restored. This prevents accidental data loss and inconsistent form states.

02

Navigation & Validation

Challenge

Users should be able to move freely between booking steps, even when some fields are incomplete. At the same time, progressing through the form and proceeding to payment must require valid information. Combining navigation, validation, and data persistence too closely can either restrict users unnecessarily or cause unfinished inputs to be lost.

Implemented Solution

Draft data and validation status are handled separately. Form inputs are saved regardless of whether they are complete, while the "Next" button validates the current step using Zod. Previously completed steps are revalidated when relevant information changes, and the full booking data is validated again on the server before checkout. This preserves user flexibility without compromising data integrity.

03

Payment Confirmation & Failure Recovery

Challenge

Sending booking notifications during checkout can increase the time customers spend waiting. However, sending them only after a successful payment creates another risk: if email delivery fails, the customer service team may never receive the details of a paid booking.

Implemented Solution

Booking data is temporarily stored in Redis with a one-hour expiration before payment. Once PayPal confirms the payment, Resend handles the email notification. If delivery fails, the stored booking information can be recovered manually and the notification resent. This reduces perceived checkout latency while providing a pragmatic recovery mechanism.

Potential Improvement: For stronger reliability guarantees, permanent booking storage combined with a persistent job queue and automated retries would eliminate the need for manual recovery.
